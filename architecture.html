Components

Component Role
Cowrie Medium-interaction SSH honeypot with an emulated shell. Writes JSON events, TTY recordings and captured files. Never executes attacker commands.
Collector Tails the Cowrie JSON log with a persisted offset, handles rotation and partial lines, and is idempotent: event ids are deterministic (UUIDv5 of the raw line), so re-ingest never duplicates. Bad lines go to a dead-letter table.
Normalizer and store Map Cowrie events to a stable taxonomy, convert times to UTC, and write each event in one transaction. Raw rows are saved first, derived rows in separate savepoints, so an analysis failure never loses telemetry.
Command parser Splits shell lines into emulated processes, file operations and network intents, always labelled derived.
Detection Bounded rules plus contextual checks (download, chmod, execute chains). Produces categories with confidence, MITRE ATT&CK techniques with evidence and event ids, and a risk score.
Payload analysis SHA256, size, magic bytes, ELF metadata, printable strings, entropy. Files are only read.
Intel Asynchronous IP enrichment (Team Cymru ASN data via DNS, optional reverse DNS, optional local MaxMind-format database).
Housekeeping Closes stale sessions, applies retention, raises disk alerts, runs analytics jobs (campaign hashes, payload enrichment, per-IP credential techniques).
API and dashboard JWT-authenticated REST, first-message-authenticated WebSocket, Prometheus metrics, a React 19 + TypeScript + Vite dashboard served by the same process. Two roles: admin and an optional read-only viewer.
Notifier (opt-in) Webhook, Telegram and e-mail alert channels with per-channel threshold, rate limit and digest.
Root status exporter A small root oneshot that exports unit state, watchdog events and blocked-egress counters to a file that the unprivileged backend reads as untrusted input.
systemd and nftables Units with restart and hardening; a rendered nftables ruleset implements the containment.

Data flow of one command

  1. The attacker types a download-and-run line in the emulated shell.
  2. Cowrie logs the command and the output bytes. The download itself never succeeds: Cowrie refuses non-global addresses by itself, and any real connection attempt by the honeypot user is dropped by the firewall.
  3. The collector reads the line; the store inserts the event and the command, derives the emulated processes, a file operation and a network intent with status attempted, and runs detection.
  4. Severe categories with confidence of at least Likely raise a deduplicated alert; events, sessions and alerts are pushed to the live view over the WebSocket.
  5. Every alert passes one choke point where suppression rules can demote or hide known noise (ADR 0013); events and sessions are never altered and alerts are never deleted.

Design choices (see Decisions)

  • Cowrie binds tcp/22 directly with a single capability, avoiding NAT rules (ADR 0002).
  • SQLite in WAL mode with a PostgreSQL-compatible schema and versioned migrations (ADR 0004).
  • One Python process serves collector, API, WebSocket and dashboard (ADR 0005).
  • Offline release tarball with a wheelhouse; the host needs no internet access to install (ADR 0006).
  • The dashboard listens on loopback only by default and is reached through an authenticated tunnel.
