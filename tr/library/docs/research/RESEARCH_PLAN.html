Research Plan - honeypot-intelligence

Date: 2026-10-05
Phase: PHASE 2 - RESEARCH
Duration: Indefinite (until architecture decisions finalized)

1. Primary Research Objective

Complete technology research and comparison to finalize architecture decisions for the SSH honeypot platform.

2. Research Questions

Question Priority Evidence Required Stop Condition
1. What SSH honeypot technology best matches our requirements? HIGH Technology comparison matrix with features, implementation complexity, maintenance requirements Cowrie recommended (87/100 score)
2. What are Cowrie installation and configuration requirements? HIGH installation guide, Docker options, system dependencies, security configurations Verified on target VM (Python 3.10, 4 vCPU, 7GB RAM)
3. What Python packages are required for the backend API and supporting services? MEDIUM requirements.txt or pip install commands for all backend components Cowrie dependencies: bcrypt, cryptography, twisted, attr, etc.
4. What are the containment and security requirements for the honeypot? HIGH nftables default-deny policy, filesystem isolation, user separation, payload quarantine strategy Default-deny outbound, unprivileged cowrie user, isolated quarantine
5. What firewall configuration is required to preserve management access while containing the honeypot? HIGH nftables ruleset for management SSH access (port 22) and honeypot (port 2222), rollback procedure Backup existing policy, implement default-deny
6. What are the requirements for the real-time event pipeline architecture? MEDIUM Event flow design, real-time transport (SSE/WebSocket), database schema, storage strategy SSE for events, WebSocket for terminal sessions
7. What are the minimum retention and backup requirements? LOW Database backup strategy, log retention policies, monitoring and alerting SQLite with WAL mode, automated daily backups
8. What are the integration requirements with external intelligence sources? LOW MaxMind GeoLite2/ASN database integration, optional threat-intel API Offline DB primary, API optional
9. What are the user authentication and authorization requirements for the dashboard? HIGH Authentication mechanism, authorization levels, secure session management Session-based authentication (TBD)
10. What are the ongoing support and maintenance requirements? LOW Package updates, log rotation, health checks, service restart procedures Systemd service management, logrotate

3. Research Methodology

3.1 Technology Evaluation

  1. Cowrie (Primary Candidate) - Evaluation: SSH protocol coverage, session recording capabilities, command logging, file capture - Evidence: GitHub repository, installation instructions, Docker image, documentation - Target: Verify installation on [gizlendi]

  2. Alternative Technologies - OpenCanary: Port-scan detection (for future expansion) - Honeytrap: Centralized logging (for multi-honeypot deployment) - Dionaea: Malware capture (if threat intelligence requires) - Conpot: ICS/SCADA (out of scope for SSH honeypot)

3.2 Implementation Feasibility

  1. Technical Requirements - Python Environment: Python 3.10+ (matches target VM) - Hardware Constraints: 4 vCPU, 7GB RAM, 100GB disk (target VM constraints) - Software Availability: Ubuntu package repository, pip availability - Network Requirements: Outbound containment with DNS/NTP access

  2. Security Requirements - Firewall: nftables default-deny outbound - Isolation: Unprivileged user, chroot-like filesystem - Payload Management: Quarantine with SHA256 hashes - Authentication: Secure credential management

3.3 Performance Requirements

  1. Resource Usage - Memory: <2GB for Cowrie + backend + database - Disk: ~50GB total with retention policies - Network: Low bandwidth for event streaming

  2. Availability - Uptime: 99.5% for production deployment - Recovery: Automated restart on failure
