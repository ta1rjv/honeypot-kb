Findings (static): - All four files are byte-identical prefixes of ONE binary (cmp -n against the shortest copy). The four different hashes are an artifact of truncation, not four samples. - None is complete: the ELF header points to section headers at offset 30304408, so the full binary is > 29 MB. Cowrie download_limit_size = 20971520 caps uploads at 20 MiB (#13 hit it exactly); the others ended when the session dropped (~301 s, "Connection lost"). - Type: ELF 64-bit x86-64, Go, dynamically linked. - Capability indicators (strings): main.credential, attackqueue *[]main.credential, github.com/pkg/sftp, github.com/msteinert/pam, github.com/shirou/gopsutil, main._rig_config with Xmrig_enabled, Xmrig_algo, Xmrig_poolAddr, Xmrig_poolUser, Xmrig_poolPass, Xmrig_nicehash, main._update, public-IP lookups (api.ipify.org, ipinfo.io, ip.seeip.org, ipgrab.io, checkip.amazonaws.com), discord.com, 0.0.0.0:2210. - Assessment (MEDIUM confidence, string-based, not executed): a self-spreading SSH brute-force bot that uploads itself as sshd over SFTP, carries an XMRig mining configuration, a PAM module reference (possible credential capture) and a Discord channel (likely reporting). Pool address and wallet were not found in the captured prefix. Family name UNKNOWN (no hash lookup done).

Impact on the honeypot: none. The file was only written by Cowrie's emulated SFTP; it was never executed, and the attacker sessions ran 0 commands.

Collection gaps found: 1. Collector does not mark SFTP uploads as available (available=0, size=NULL, stored_path=NULL) although the file exists - DB/dashboard understate the captured evidence. 2. download_limit_size (20 MiB) truncates this > 29 MB sample; a complete copy would need a higher limit.
