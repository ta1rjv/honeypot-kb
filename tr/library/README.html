Honeypot Intelligence Platform

Contained SSH honeypot (Cowrie) with a FastAPI backend and a React SOC dashboard: command-level session recording, live terminal view and TTY replay, payload capture and static analysis, IP/ASN intelligence, evidence-based attack classification with MITRE ATT&CK mapping, and strict egress containment so the honeypot can never be used against third parties.

Features

  • Honeypot: Cowrie 3.0.15 on tcp/22 (emulated shell, SCP/SFTP capture, TTY recordings).
  • Collector: tails cowrie.json with offset persistence, rotation handling, idempotent ingest (deterministic event ids), dead-letter table for bad lines.
  • Normalized model: sessions, auth attempts, commands, emulated processes, file operations, network intents, payloads, classifications, MITRE mappings, alerts (SQLite WAL, PostgreSQL-compatible schema, versioned migrations).
  • Analysis: shell command parsing, incremental per-session detection (recon, credential access, persistence, download/execute chains, miners, lateral movement intents), confidence levels Suspected < Likely < Observed < Confirmed with evidence and event ids.
  • Payloads: sha256, file type/MIME, printable strings (URLs, IPs and shell keywords ranked first), ELF/script metadata; bytes are read, never executed or served.
  • IP intelligence: Team Cymru ASN/country via DNS, optional reverse DNS, optional local MaxMind-format database.
  • API: REST + WebSocket (first-message JWT auth), public health and Prometheus metrics.
  • Dashboard views: Overview (time range, KPI deltas, heatmap, funnel, world map, top lists), Live Attacks, Live Terminal, Sessions, Session detail, Session compare, IP Intel (activity, risk breakdown, same ASN, campaigns), Campaigns (including heuristic script clusters), New in range, Credentials, SSH fingerprints (HASSH, client versions), MITRE ATT&CK matrix, Alerts (search, bulk acknowledge, notes), Payloads (entropy, extracted IoCs, truncated-copy families), IoC Export (CSV, JSON, STIX 2.1; heuristic indicators opt-in), Processes, Files, Network, Attack Analysis, Timeline, Time patterns, Weekly report (JSON/Markdown download), Replay, Search, Health (trends, systemd units, host status, containment trend, webhook, Telegram and e-mail state). Dark and light theme, keyboard shortcuts (g + key, /), lazily loaded views, shareable filter links (Copy link), sticky table headers.
  • Roles (0.4.0): the admin plus an optional read-only viewer account (HPINTEL_VIEWER_USER, HPINTEL_VIEWER_PASSWORD_HASH) that reads everything but cannot acknowledge alerts or add notes.
  • Alert suppression rules (0.5.0): demote or hide known-noise alerts by command hash, kind, source IP/CIDR/ASN or "no payload transferred", managed from the dashboard Suppression view; events and sessions are never touched and alerts are never deleted (ADR 0013).
  • Webhook alerts (0.4.0, opt-in): HMAC-signed HTTP(S) POST per new alert to one receiver, with nftables egress opened only for the backend uid to one address and port (ADR 0011).
  • Telegram and e-mail alerts (0.5.0, opt-in; HP_TELEGRAM_*/HP_SMTP_* open one egress rule each): per-channel severity threshold, rate limit and an optional digest of what stayed below the threshold (STARTTLS or TLS only, certificate always verified; secrets only in hpintel.env) (ADR 0015).
  • Operations: systemd units with restart and hardening, retention for the database and Cowrie files, offline release tarball, install/upgrade/rollback scripts.

Security

Containment before realism, no real execution, no secrets in the repository. See SECURITY.md, THREAT_MODEL.md and INCIDENT_RESPONSE.md. Captured malware and attacker data are never committed.

Limitations

  • Skilled attackers can fingerprint Cowrie (medium interaction).
  • Attacker downloads fail by design (no egress); payloads are captured only when pushed via SCP/SFTP.
  • Dashboard over plain HTTP; the default is loopback plus SSH tunnel. Any other exposure needs a TLS reverse proxy.
  • setup.sh targets x86_64 hosts with systemd. Not verified: IPv6 listening. Site note on reboots: a reboot of the production host was VALIDATED on 2026-10-10 (18:38 UTC) with release 0.2.x/0.3.0; a production reboot with release 0.3.1 and later is NOT RUN; scenario-based reboots were VALIDATED on disposable VMs.
  • PostgreSQL support is designed for but not tested.
  • Geolocation (city/coordinates) needs a user-provided MaxMind-format database.
