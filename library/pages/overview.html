Project Overview

Goals, scope and the data captured by the Honeypot Intelligence platform, in one page.

Goal #

The platform exists to observe real internet attackers safely and turn the raw telemetry into usable intelligence: who connects, which credentials they guess, what they run after a login, which files they push, and how their behaviour maps to MITRE ATT&CK. The captured data is used for security research and evaluations, which is why all of it is kept (see About and ADR 0010).

The guiding rule of the project is: realism never overrides containment. The decoy may be less convincing than a real server, but it must never be able to touch anyone else.

What is in scope #

  • An internet-facing SSH decoy on tcp/22 (medium interaction, emulated shell; Cowrie 3.0.15). Telnet is disabled.
  • Command-level recording, TTY recordings with live view and replay, SCP/SFTP file capture.
  • A normalized data model (sessions, authentication attempts, commands, emulated processes, file operations, network intents, payloads, classifications, MITRE mappings, alerts).
  • Rule-based detection with an explicit evidence and confidence model.
  • IP and ASN enrichment from DNS-based sources, with optional reputation lookups planned.
  • A read-mostly web dashboard for analysts and opt-in alert notifications.
  • Default-deny network containment and an availability watchdog.

What is out of scope #

  • Real command execution: attacker commands are never executed on the host.
  • Active contact with attacker infrastructure from the honeypot host (blocked by design; a separate out-of-band retrieval design is only PROPOSED, see ADR 0014).
  • Telnet and other protocols; high-interaction deployments.
  • Attribution: IP and ASN data is labelled external intelligence and is never treated as identity.

What is captured #

Data Source Notes
Connections and SSH client versions Cowrie JSON log Includes HASSH fingerprints of the client key exchange.
Authentication attempts Cowrie JSON log Usernames and passwords tried by attackers; the decoy accepts some of them.
Commands Cowrie JSON log, parsed by the backend Parsed into emulated processes, file operations and network intents (labelled derived).
Terminal output Cowrie TTY recordings Used for live view and replay.
Uploaded files Cowrie downloads (SCP/SFTP) SHA256, type, entropy and printable strings; read only, never executed or served.
Failed download attempts Parsed commands Attacker wget/curl fetches fail by design and are recorded as intents.
Source IP intelligence Team Cymru DNS, reverse DNS, optional local database Labelled "external intelligence".

Current state #

The project is in the MAINTENANCE phase as of 2026-10-16: release 0.5.1 is deployed on the production VDS, and the 0.6.0 enrichment work is on a work branch (see Intelligence pipeline and Operations history). Requirements and their states are in the requirements document; the live numbers are on the home page and in the attack landscape.
