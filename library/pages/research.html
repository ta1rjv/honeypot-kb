Three published research documents and one unpublished study back the design. Truth levels follow the sources.

Honeypot technology comparison (2026-10-05) #

Full comparison. Criteria with the highest weight were SSH focus, command-level and TTY recording, file-upload capture with hashing, isolation, installation maturity and structured output. Outcome:

Candidate Assessment in the comparison
Cowrie Excellent match: SSH and Telnet emulation, per-command JSON log, replayable TTY recordings, SFTP/SCP capture, runs unprivileged. Selected (ADR 0001).
OpenCanary Poor match for interactive SSH: port monitoring, no shell emulation or file capture. Optional secondary.
Honeytrap Extensible Go framework; SSH only through Cowrie integration. Fairly good for centralized management, not a primary SSH honeypot. Optional secondary.
Dionaea Poor match: malware capture through other protocols, no SSH. Not selected.
Conpot Irrelevant: industrial-control protocols. Not selected.

Research plan #

Research plan: the objective was to finalize the technology choice for an SSH honeypot platform. Ten questions were asked, ranked by priority, each with required evidence and a stop condition: technology match, Cowrie installation requirements, backend packages, containment and security, a containing firewall, real-time event pipeline, retention, external intelligence sources, dashboard authentication and ongoing maintenance. The answers became the early ADRs (0001 to 0008).

Honeypot detectability (2026-10-08) #

A detectability study of the Cowrie emulation exists (an input to release 0.3.1). It is not published: how to tell that a host is a medium-interaction emulation is deliberately kept out of this public site. The only public statement is the accepted residual risk that a skilled attacker can detect an emulation.

Enrichment providers (2026-10-16) #

Enrichment providers research supports the planned 0.6.0 work (ADR 0018, see Intelligence pipeline). Official provider pages were read on 2026-10-16 for the five candidates (AbuseIPDB, GreyNoise Community, Shodan InternetDB, URLhaus, VirusTotal v3): endpoints, authentication, free limits, verdict fields and terms notes, each tagged VERIFIED, strongly supported or UNKNOWN. A single DNS snapshot showed that several providers sit behind CDNs or load balancers with changing address sets, which is why the design pins a short list of addresses and offers a refresh check; multi-day address stability is UNVERIFIED. The note also covers YARA tooling, sharing formats and a measured baseline of the production host.
