Operations History

Release timeline from 0.2.0 to 0.5.1 with production upgrade dates, downtime figures and recorded test results.

3 sections

On this page

On this page

  • Release timeline
  • Production upgrade notes

The platform runs on one rented virtual server. Releases are validated on a disposable test VM first, then installed on production with the guarded setup.sh rerun; each production upgrade has a report with MEASURED evidence. Detailed release notes, test logs, reports and runbooks stay in the private repository and are not published.

Truth levels: release contents are IMPLEMENTED; the production upgrades listed are MEASURED in their reports; downtime figures are measured from service timestamps.

Production upgrade notes #

  • 0.3.1: upgrade and a read-only security audit. Only the intended ports answered from outside; no containment gap.
  • 0.4.0: 15 of 15 post-install checks passed, database counts not lower, firewall file unchanged, new third-party sessions ingested after the upgrade. Not run: authenticated API checks and a production reboot.
  • 0.4.1: upgrade with follow-ups of the audit, verified live.
  • 0.5.0: upgrade in 1 min 26 s, migrations 11-13, firewall ruleset hash identical before and after, row counts not lower, seed suppression rule created, MITRE backfill completed without changing the alert count.
  • 0.5.1: upgrade in 1 min 26 s, migration 14, ruleset hash identical, hpintel still without capabilities. Authenticated feature checks on production were NOT RUN.

Reboot status: a reboot of the production host was VALIDATED on 2026-10-10 (18:38 UTC) with release 0.2.x/0.3.0. A production reboot with release 0.3.1 and later is NOT RUN. Scenario-based reboots (reboot persistence after install and upgrade) were VALIDATED on disposable VMs. Other recorded facts: fresh installs were validated on a disposable VM (0.3.x); IPv6 was never tested because the host has none.

Recorded automated test results #

From the project's test log (each line is a recorded run, not a promise for later versions):

  • 0.4.0: 1235 backend tests passed (2026-10-11).
  • 0.5.0 release candidate (2026-10-16): 1568 backend tests passed, 0 failed; 731 deployment tests passed with 3 skipped (opt-in environment tests); dashboard build passed with 0 vulnerabilities reported.
  • Test areas: normalization of every event type, command parser, detection and confidence, payload analysis, API and WebSocket authorization, security checks (injection, path confinement, adversarial input), installer, firewall renderer golden tests and the installation wizard.

Not tested, as listed in the project: PostgreSQL backend, a clean-clone install from Git on a fresh VM, webhook delivery to an external receiver in production.
