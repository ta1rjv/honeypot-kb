2. Component Analysis

Cowrie

Source: https://github.com/cowrie/cowrie
Type: SSH/Telnet honeypot
Runtime: Python 3.11+ (Twisted framework)
Install: pip, Docker, git checkout

Feature Status Details
SSH Protocol (yes) Full SSH emulation with fake shell
Telnet Protocol (yes) Telnet honeypot with command logging
SFTP/SCP (yes) File upload capture (downloads stored in var/lib/cowrie/downloads/)
Session Recording (yes) TTY sessions in User Mode Linux script format, replayable via playlog
Command Logging (yes) Per-command audit log in JSON (var/log/cowrie/cowrie.json)
Auth Attempts (yes) Username/password logging with brute-force detection
Source IP/Port (yes) Captured in session metadata
Real-time Events (yes) JSON log stream, can be consumed via file/polling or hpfeeds
Isolation (yes) Filesystem isolation (chroot-like via fake fileshystem), can run unprivileged
Proxy Mode (yes) Proxy to backend server for high-interaction
Docker (yes) Official Docker image available
Dependencies Python 3.11+, Twisted[conch], bcrypt, cryptography, attr, lark, treq

Assessment: EXCELLENT match. Purpose-built for SSH honeypot with all required telemetry features. Mature (active development, large community). JSON audit logs enable easy integration with custom backend.

OpenCanary

Source: https://github.com/thinkst/opencanary
Type: Multi-service port monitoring daemon
Runtime: Python 3.10+
Install: virtualenv + pip

Feature Status Details
SSH Protocol (warn) Port 22 listener but minimal interaction (no shell emulation)
Telnet Protocol (no) Not focused on Telnet
SFTP/SCP (no) No file capture
Session Recording (no) No session/shell recording
Command Logging (no) No command-level interaction
Auth Attempts (yes) Login attempt logging
Real-time Events (yes) JSON config-based logging output
Isolation (warn) Runs as daemon, no filesystem isolation
Docker (warn) Community Docker images, not official
Scope Broad SNMP, SMB, HTTP, FTP, MySQL, MSSQL, etc. (15+ services)

Assessment: POOR match for SSH honeypot. Designed for port-scan/detection alerting, not interactive session recording. Would need to be combined with Cowrie for SSH interaction. Overkill for our specific requirements.

Honeytrap

Source: https://github.com/honeytrap/honeytrap
Type: Extensible honeypot framework (Go)
Runtime: Go (compiled)
Install: Docker, source compilation

Feature Status Details
SSH Protocol (warn) Via Cowrie/attackers-proxy integration
Telnet Protocol (warn) Similar to SSH
SFTP/SCP (no) No native capture
Session Recording (no) Via external tools (Cowrie proxy)
Command Logging (warn) Delegated to backend honeypots
Real-time Events (yes) Elasticsearch, Kafka, Splunk, File output
Isolation (yes) LXC containers, remote directors, network isolation
Docker (yes) Official Docker image
Multi-Protocol (yes) One port handles multiple protocols via payload detection
Centralized (yes) Server-agent architecture for managing multiple honeypots
Scope Broad TCP/UDP, service emulation, attacker redirection

Assessment: FAIRLY GOOD for centralized management but NOT a primary SSH honeypot. Would serve as orchestration layer, not primary SSH honeypot. Architecture: Agent connects to Server. Not the right primary component for our SSH-focused requirements.

Dionaea

Source: https://github.com/DinoTools/dionaea
Type: Malware-capture honeypot
Runtime: Python + C/C++ (libemu, CMake)
Install: CMake compilation, Docker

Feature Status Details
SSH Protocol (no) No SSH support
Telnet Protocol (no) No Telnet support
File Capture (yes) Malware capture via protocol emulation
Session Recording (no) No interactive session recording
Command Logging (no) No command-level interaction
Shellcode Detection (yes) Via libemu
Real-time Events (yes) JSON, SQLite, hpfeeds
Isolation (warn) No built-in isolation (runs as service)
Protocols Broad SIP, HTTP, FTP, SMB, TFTP, MQTT, MySQL, MSSQL, etc.
Docker (yes) Dockerfile available

Assessment: POOR match for SSH honeypot. Designed for malware capture via vulnerable service emulation, not SSH interaction. Completely unrelated to SSH session recording requirements.

Conpot

Source: https://github.com/Conpot-org/conpot
Type: ICS/SCADA honeypot
Runtime: Python 3
Install: pip, Docker

Feature Status Details
SSH Protocol (no) No SSH support
Session Recording (no) No session recording
ICS Protocols (yes) Modbus, S7comm, BACnet, SNMP, HTTP, FTP, TFTP
File Capture (yes) Firmware/credential capture
Real-time Events (yes) JSON output
Isolation (warn) Basic (runs as daemon)
Docker (yes) Official Docker image

Assessment: IRRELEVANT. ICS/SCADA honeypot, not SSH-focused. Should not be selected unless ICS protocols are required (no current requirement).

4. Recommendation

Primary Honeypot: Cowrie (yes)

Cowrie is the clear winner for SSH honeypot:

  1. Perfect requirement match: SSH/Telnet honeypot with full session recording, command logging, SFTP/SCP payload capture
  2. Mature and active: Well-maintained with large community
  3. JSON audit logs: var/log/cowrie/cowrie.json enables easy integration with custom backend
  4. Session replay format: Logs in User Mode Linux script format, replayable via playlog
  5. Python-based: Matches backend stack; dependencies are well-defined
  6. Docker support: Can run in container for additional isolation
  7. Proxy mode: Can proxy to backend for high-interaction scenarios

Secondary/Optional: OpenCanary

Not recommended as primary. Only useful as a port-scan detection layer if multi-protocol deception is needed later. No value for current SSH-focused requirements.

Secondary/Optional: Honeytrap

Could be used as a centralized event collection agent (server-agent model) if multiple honeypot instances are deployed. Not a primary component for Phase 1.

Not Selected: Dionaea, Conpot

Completely irrelevant for SSH-focused requirements. No overlap in protocols or use cases.

5. Architectural Decision

Recommended Stack

Layer Component Technology
Honeypot SSH/Telnet honeypot Cowrie
Event Collector JSON log ingestion Python asyncio
Event Bus In-process + SQLite SQLite WAL
Database Event storage SQLite (PostgreSQL-compatible schema)
Backend REST API + SSE Python (FASTAPI or similar)
Frontend SOC dashboard Node.js + React
Firewall Containment nftables (default-deny outbound)
IP Intelligence Offline DB MaxMind GeoLite2 + ASN database
Classification Event analysis Python rules engine

Isolation Strategy

  1. Cowrie process isolation: Run Cowrie under dedicated cowrie unprivileged user
  2. nftables containment: default-deny outbound except to approved destinations
  3. Filesystem isolation: Cowrie fake filesystem already provides containment
  4. Admin SSH preserved: Port 22 managed SSH preserved; Cowrie on alternate port

Port Architecture

  • Port 22: Management SSH (untouched, firewall-protected)
  • Port 2222 (or 8080): Cowrie SSH honeypot (behind nftables)
  • Port 8080 (or 8000): Backend API (localhost only or authenticated)
  • Port 3000 (or 8081): Frontend dashboard (authenticated via reverse proxy)
