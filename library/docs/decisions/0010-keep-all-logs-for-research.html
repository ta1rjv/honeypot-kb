ADR 0010: Keep all captured logs for research (effectively unlimited retention)

Status: accepted (2026-10-08)

Context: honeypot-intelligence is an attack-intelligence research platform. The owner uses the captured data in scientific research and evaluations, where losing older sessions, events, payloads or raw Cowrie logs to automatic pruning would damage the dataset. The defaults prune data on two independent paths:

  1. Database rows: HPINTEL_RETENTION_*_DAYS (events 180, sessions 365, network 180, payloads 365) applied by backend/hpintel/housekeeping.py.
  2. Raw Cowrie files on disk: cowrie-retention.service (daily timer) deletes rotated JSON logs older than 30 days, TTY recordings older than 180 days and downloads older than 365 days.

HPINTEL_RETENTION_*_DAYS has a minimum of 1 (0 or a disable sentinel is not supported), so "keep everything" is expressed as a very large number.

Decision: retain all captured data effectively forever on both paths.

  1. Set every HPINTEL_RETENTION_*_DAYS to 36500 (about 100 years) in the production env file and in deployment/config/hpintel.env.example.
  2. Set every cowrie-retention.service window (find -mtime +N) to 36500 in the unit header and all three ExecStart lines, in deployment/systemd/cowrie-retention.service. The timer stays enabled so the mechanism remains in place and auditable; it simply never matches a file.
  3. Keep the disk-usage alerts active and unchanged (HPINTEL_DISK_WARN_PERCENT 85, HPINTEL_DISK_CRITICAL_PERCENT 95). Unlimited retention trades disk for completeness, so the operator must still be warned before the disk fills (THREAT_MODEL.md T11).

Consequences: - No research data is lost to automatic pruning. - Disk grows without bound; the operator monitors the disk alerts and plans capacity or archival. The disk horizon is long, but capacity is now an operator responsibility. - Operators who want bounded retention lower these numbers; the mechanism and its validation are unchanged. - Applying this to an already-running host requires editing the live env file and the live unit, then systemctl daemon-reload and restarting hpintel.service (see docs/OPERATIONS.md, "Keep all logs").
