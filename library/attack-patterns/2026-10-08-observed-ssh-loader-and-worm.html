Pattern 1 - Go SSH loader capability probe (Observed) #

A SSH-2.0-Go client logs in with common root passwords and runs, in one shot:

export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:$PATH
uname=$(uname -s -v -n -m 2>/dev/null || /bin/uname -s -v -n -m 2>/dev/null || busybox uname ... )
printf "#!/bin/bash\necho \"xxxxxx\"\n" > filter && chmod +x filter && ./filter && rm -rf filter

Meaning: system profiling (uname) plus a write/chmod/execute/cleanup test that expects the literal output xxxxxx. It is a pre-flight check, not malware; the real second stage is only fetched if the probe succeeds. In this capture the loader did not proceed to a download.

  • Categories: reconnaissance, downloader, malware_deployment (Observed; fires on chmod +x). MITRE: T1082, T1222.002, T1059.004.
  • Evidence: sessions c697370ce14c, 49937cef838a, 163f526ca1c9 (195.178.110.232, 2026-10-07 23:11Z..23:16Z); 05b1ad5b146e, c2875e618d68 (92.118.39.50, 2026-10-08 12:40Z..13:20Z).
  • Probe file sha256: af77b643964afd794460d28ab8a11b0ec8790cd5463abfde126613a4f3bccd32 (#!/bin/bash + echo "xxxxxx").
  • Caveat: malware_deployment at severity high overfires here (trivial echo).

Pattern 2 - SSH propagation worm, key + config drop (Observed) #

A SSH-2.0-Go client logs in (admin/admin) and stages two files for onward SSH spread:

  • /tmp/sshcfg = StrictHostKeyChecking no + UserKnownHostsFile /dev/null (sha256 00b6f15c2274420217ed3098a9f5f00545bf1793d7a324fd18a7809cbbf5b12b)
  • /tmp/key.ppk = an OpenSSH ed25519 private key (sha256 43728fbfb98bb39ff61a2db0fc2905bd6937997062b05b9ab8b186fdee18c09a; fingerprint SHA256:O/at8341SoPpKvTPvMsJSgjQm30md9VTS2it25sY0vg, comment dlr@sftp)

Meaning: classic dota/outlaw-family SSH worm. The dropped key + permissive client config let a compromised host reach further targets non-interactively. MITRE: T1105, T1098.004, T1021.004, defense_evasion.

  • Evidence: session 04bcf4604e47 (130.12.180.51, 2026-10-08 11:43Z), risk 45.
  • Containment: honeypot egress is default-deny (ADR 0003); the staged worm could not reach any third party. Confirms containment.

Pattern 3 - SFTP upload named sshd (Observed; content not captured) #

A SSH-2.0-Go client brute-forces, logs in once (root/admin) and uploads a file named sshd over SFTP - consistent with a trojanized ssh daemon for persistence. Content was NOT retained (collection gap; see TODO.md).

  • Evidence: session b4941bcc3ed4 (203.57.28.116, CN, 2026-10-08 15:03Z, sha256 d11d2e36d17dc323dbafc5e361eb51eb8e0ab078c2f50ec5bc98e5a87190aefb); session e41c17aeeb16 (123.139.242.2, CN, 2026-10-08 15:10Z, sha256 326eea0221b61a452173e9a56f515dd42b09f5de5f8f868a33e432e4ea18bc3b).
  • MITRE: T1105, persistence (T1543 candidate). Confidence: Likely (no binary).
