Assets #

Asset Why it matters
Third parties on the internet The honeypot must never become an attack platform (scanning, brute force, proxying, malware distribution, DDoS).
Host integrity (VM, LAN) Escape from the emulation or the backend would expose the LAN.
Dashboard credentials and JWT secret Admin: read access to all telemetry plus alert acknowledgement and notes. Viewer (0.4.0, optional): read access to all telemetry. The JWT secret can mint tokens for either role.
Captured telemetry and payloads Research value; payloads are live malware.

Adversaries #

  1. Automated internet attackers (botnets, scanners, credential stuffers): high volume, scripted commands, payload drops. Expected and welcome.
  2. Manual attackers who notice the emulation and try to break out of it, poison the telemetry, or attack the analysis pipeline through crafted input.

Trust boundaries #

[attacker] --SSH--> [Cowrie emulated shell, uid cowrie]  (untrusted input boundary 1)
                       | writes JSON log, tty logs, uploaded files
                       v
            [hpintel collector/parsers, uid hpintel]      (untrusted data boundary 2)
                       | SQLite
                       v
            [REST/WS API] --LAN--> [operator browser]     (rendering boundary 3)

Every field that originates in Cowrie is attacker-controlled: usernames, passwords, commands, URLs, file names, client version, HASSH, terminal size, tty content, uploaded file bytes, and the file names Cowrie derives from them.

Threats and controls #

# Threat Control Status
T1 Attacker uses honeypot to reach third parties (downloads, scans, proxy, tunnels) nftables drops all egress from uid cowrie; forward chain drop; ip_forward=0; Cowrie forwarding/tunnel disabled (direct-tcpip refused); cowrie uid also blocked on loopback Implemented, verified on VM (NETWORK.md)
T2 Real command execution on host Cowrie shell is emulated (no exec); Cowrie runs unprivileged with only CAP_NET_BIND_SERVICE, systemd hardening (ProtectSystem=strict, NoNewPrivileges, resource limits) Implemented (deployment/cowrie/cowrie.service)
T3 Payload execution during analysis Payloads are only read (hash, magic bytes, ELF header, printable strings); never executed, never served by the API, never committed to Git Implemented in backend/hpintel/payloads.py
T4 Path traversal via ttylog / file names in log events Replay path resolved and required to stay inside the tty directory; payload paths derived from validated sha256 only; SPA static paths confined to static root Implemented; covered by tests
T5 SQL injection via attacker strings SQLAlchemy Core with bound parameters; LIKE patterns escaped Implemented; covered by tests
T6 Stored XSS in dashboard React text rendering only (no raw HTML), CSP default-src 'self', X-Frame-Options DENY Implemented
T7 Pipeline poisoning / DoS (malformed lines, huge input, duplicate replay) Per-line parse errors skipped and counted; deterministic event ids (uuid5 of raw line) make re-ingest idempotent; bounded bus queues drop for slow consumers; Cowrie download size limit 64 MiB (new installs; existing hosts after the DEPLOYMENT.md upgrade step, 20 MiB before); systemd MemoryMax Implemented; review findings tracked in TODO.md
T8 Dashboard brute force / token theft / privilege misuse scrypt password hashes, HS256 JWT with expiry, 10 failures / 15 min per username plus a global cap of 30 / 15 min, token never in URLs (WS first-message auth), sessionStorage, no CORS. Roles (0.4.0): the token role claim is re-checked against the configured admin and viewer accounts on every request (removed or renamed accounts lose their tokens); every non-GET route except login requires the admin role (viewer: 403); login verifies exactly one hash for any username Implemented; roles IMPLEMENTED (covered by tests), VALIDATED on [gizlendi] (2026-10-11: viewer 403 on writes, admin 200)
T11 Disk exhaustion by log/payload flood Retention jobs (backend DB and Cowrie files), disk usage alerts at warn/critical thresholds Implemented; see OPERATIONS.md

Residual risks #

  • Availability: a watchdog restarts the honeypot if it stops responding (VALIDATED). Each restart drops open attacker sessions.

  • Cowrie or Twisted vulnerabilities could give code execution as cowrie; egress is still blocked for that uid, but local privilege escalation in the container is not prevented by this project.

  • DNS egress remains open for non-honeypot users.
  • The viewer role is read-only but sees all telemetry, including attacker credentials.
