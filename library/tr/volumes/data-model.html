Defined in backend/hpintel/db.py (SQLAlchemy Core). The schema uses portable types only so it runs on SQLite (current) and PostgreSQL (planned).

Conventions: - Timestamps are ISO 8601 UTC strings YYYY-MM-DDTHH:MM:SS.ffffffZ (sortable as text). - JSON values are stored as TEXT. - Every attacker-controlled string is clipped to its column length. - evidence columns: observed (a Cowrie fact) or derived (parsed from a command line). - Schema versions are recorded in schema_migrations; python -m hpintel.cli migrate applies pending migrations (also run at service start).

Version Change

3 index ix_commands_session_ts
4 analytics indexes ix_payload_events_ts, ix_ip_intelligence_asn, ix_ip_intelligence_country, ix_sessions_hassh
5 alert_notes and system_samples tables

7 payloads.entropy, entropy_bytes, head_sha256, extracted_iocs; index ix_payloads_head_sha256; payload_relations table
8 sessions.hassh_algorithms (TEXT), sessions.command_norm_hash (VARCHAR(64)); index ix_sessions_command_norm_hash; index ix_authentication_attempts_timestamp created if missing (0.4.0)
9 host_status_samples, watchdog_events, f2b_ban_episodes tables (0.4.0)
10 alert_deliveries and alert_delivery_cursors tables; index ix_alert_deliveries_channel_status (0.4.0)
11 alert_ack_events table (acknowledgement audit trail); no columns added to alerts, no backfill (0.5.0)
12 alert_suppression_rules and suppressed_alerts tables; alerts.original_severity and alerts.suppression_rule_id columns (added only when missing); seed rule known-probe-filter-d882d096 (0.5.0)
13 notification_digests table (digest cursors of the Telegram and e-mail channels, ADR 0015; 0.5.0)

Migrations 6, 7, 8 and 12 add columns with ALTER TABLE ... ADD COLUMN only when the column is missing, and migrations 8-13 create tables and indexes with checkfirst, so a re-run after a partial failure is safe. A fresh database gets every column and index from migration 1.

After an upgrade to 0.4.0, hassh_algorithms (from the stored cowrie.client.kex events) and command_norm_hash of existing sessions are filled by the housekeeping jobs in bounded batches, or at once with python -m hpintel.cli backfill-analytics. Sessions whose kex event data was already cleared by retention get "".

Tables #

Table Key Purpose / important columns
events event_id (UUIDv5 of raw line) Every normalized event: timestamp (UTC), original_timestamp, session_id, source (cowrie), event_type, severity, src_ip, summary, raw_data (original JSON line), normalized_data. Re-ingesting the same line is a no-op.
sessions id (Cowrie session id) Connection lifecycle: src_ip/src_port, dst_ip/dst_port, start_time, end_time, duration_ms, status (active/closed), client_version, hassh, term_width/height, username, password (attempted honeypot credential), login_success, auth_attempts, command_count, ttylog, disconnect_reason, risk_score, categories (JSON), command_hash (sha256 of the first 500 commands joined by newlines, filled by a background job for closed sessions; "" when the command rows no longer exist), command_hash_count (the command_count the hash was computed for; the job recomputes the hash when they differ), command_norm_hash (sha256 of "v1\n" plus the same commands normalised by normalize_command_v1: heuristic script cluster key, API.md; "" when the commands are gone), hassh_algorithms (the HASSH algorithm string of cowrie.client.kex, clipped to 4096 characters; "" when the event carried none or its data is gone; NULL until ingested or backfilled; not returned by session listings).
source_ips ip Per-attacker aggregates: first/last seen, sessions, auth attempts/successes, commands, payloads, risk score.
ip_intelligence ip External intelligence: ASN, AS name, prefix, country, registry, allocation date, rDNS, city/coordinates (optional mmdb), is_private, sources, error, fetched_at.
hosts sensor Honeypot sensors and their address.
authentication_attempts id Each login attempt: method (password/publickey), username, password, key fingerprint, success, event id.
credentials id Aggregated username/password pairs with attempts, successes, first/last seen.
commands id Each command line typed: seq within the session, input, known (false when Cowrie reported the command as not found).
processes id Emulated process tree derived from command lines: parent, executable, argv, known, emulated (always true: nothing is executed on the host).
files id File operations (read/write/delete/chmod/execute/upload/download) with sensitive class (e.g. credentials, ssh keys, cron) and evidence.
network_connections id Inbound connections (observed) and attempted outbound activity (derived from wget/curl/nc/ssh/... or observed from Cowrie download events): direction, tool, dst_ip, dst_port, url, status (accepted, closed, attempted, succeeded, failed, blocked), evidence.
payloads sha256 Captured files: filename, size, MIME/file type, strings sample, metadata (ELF class/arch/endianness, UPX hint, string counts), source URL, stored_path (never exposed by the API), available, times_seen, entropy (Shannon bits per byte over the first 4 MiB), entropy_bytes (bytes measured; 0 = file not readable, not retried), head_sha256 (sha256 of the first 64 KiB, groups truncated copies), extracted_iocs (JSON: URLs, IPv4, BTC/XMR/ETH wallets found by heuristics, at most 100 values per kind and 8 KiB).
payload_relations id, unique (sha256_prefix, sha256_full) Result of a byte-by-byte compare of two payloads with the same head_sha256: relation = prefix, differs, unreadable or too_large (over 64 MiB, not compared), checked_at. Rows whose payloads are gone are removed by retention.
payload_events id Each sighting of a payload: direction (download/upload), URL, destination file, session.
attack_classifications id Category per session with confidence, evidence (JSON list), event_ids (JSON list).
mitre_techniques id ATT&CK technique per session: id, name, tactic, confidence, evidence, event ids.
alerts id, unique dedup_key Severe classifications (>= Likely), new payloads, disk usage: severity, kind, message, acknowledged. Classification keys: class:<session>:<category>; command-level-only malware_deployment (no captured transfer, no download chain): class-ip:<category>:<src_ip>:<UTC date>, severity medium. original_severity and suppression_rule_id (migration 12, no foreign key) are set when a suppression demote rule lowered the severity.
alert_suppression_rules id, unique name Suppression rules (migration 12, ADR 0013): enabled, action (demote, suppress), target_severity, optional ANDed matchers command_hash, kind (exact or prefix*), src_ip, src_cidr, src_asn, require_no_transfer, plus expires_at, hit_count, last_hit_at, created_by, created_at, updated_at, note. At most 200 rows; never swept by retention.
suppressed_alerts id, unique dedup_key; indexes on rule_id and timestamp Alerts hidden by a suppress rule (migration 12): rule_id (no foreign key, survives rule deletion), timestamp, severity, kind, session_id, src_ip, message. One row per dedup key. Follows the events retention.
alert_notes id Analyst notes on an alert: alert_id (FK, deleted with the alert), timestamp, author, text (1-2000 characters).
system_samples id One row per housekeeping run for the Health trend: database and WAL size, disk used/free, Cowrie log size, collector counters of the running process. Follows the events retention.
host_status_samples id, unique ts One row per distinct generated_at of the root status exporter (migration 9): cowrie_active (1/0, NULL = unknown), cowrie_restarts, watchdog_failures, cowrie_egress_pkts, cowrie_egress_bytes, egress_pkts, egress_bytes (raw nftables counter values; they reset on reboot or ruleset reload, deltas are computed on read), banned_count, f2b_available. Source of the downtime and containment-trend figures. Follows the events retention.
watchdog_events id, unique (ts, kind) Cowrie watchdog events copied from the exporter (migration 9): kind (probe_failure, restart, restart_failed), detail (<= 255 characters). Follows the events retention.
alert_deliveries id, unique (alert_id, channel); index ix_alert_deliveries_channel_status (channel, status) Delivery state per alert and channel (migration 10; channels telegram and email added by ADR 0015 need no migration, the column is String(16)): alert_id (FK, deleted with the alert), channel (webhook, telegram, email), status (sent, retry, failed), attempts, last_attempt, last_error (sanitized reason, never a URL or secret).
alert_ack_events id; index ix_alert_ack_events_alert_id Append-only acknowledgement audit trail (migration 11): alert_id (FK, deleted with the alert), timestamp, actor (JWT username, <= 128), action (ack, unack), reason (<= 500 characters, nullable), bulk. One row per real state change only. Retention removes the audit history together with its alert.
alert_delivery_cursors id, unique channel Notifier high-water mark per channel (migration 10): last_alert_id (highest alert id already evaluated), updated_at. Never pruned: removing it would re-open the backlog boundary.
notification_digests channel (primary key) Digest cursor per channel (migration 13, ADR 0015; telegram, email): last_alert_id and last_suppressed_id (highest alerts / suppressed_alerts id already summarised or skipped), last_sent_at (end of the last digest interval). The first digest pass of a channel only records the current ids. Holds no alert data; never pruned (dropping it only restarts the interval).
artifacts id TTY recordings and other files linked to sessions (path, sha256, size).
collector_state name Collector position: inode and byte offset of the Cowrie log.
dead_letters id Raw lines that failed ingest deterministically (clipped), with the error type, for manual recovery.
schema_migrations version Applied migrations.

Classification vocabulary #

Confidence (weakest first): Suspected (single weak indicator), Likely (strong indicator or chain), Observed (the behaviour itself is a fact in the telemetry), Confirmed (a captured payload was then executed in the same session). Techniques record the confidence of the observation; categories record the confidence of the intent.

Categories: reconnaissance, brute_force, credential_attack, automated_scanner, downloader, malware_deployment, cryptomining, persistence, privilege_escalation, data_theft, lateral_movement, reverse_shell, destructive, defense_evasion, botnet_activity, c2, proxy_abuse. Severe (alerting at >= Likely): malware_deployment, cryptomining, persistence, reverse_shell, destructive, lateral_movement, c2, proxy_abuse, botnet_activity.

Retention (defaults, HPINTEL_RETENTION_*) #

Data Days Rule
sessions and their child rows 365 by start_time
events 180 events of still-retained sessions are kept with raw/normalized data cleared; unowned events deleted
network connections 180 unless owned by a retained session
payload rows 365 by last_seen
dead letters 180 same as events
system_samples, host_status_samples, watchdog_events 180 same as events (by timestamp / ts)
f2b_ban_episodes 180 same as events, closed episodes only (by last_seen); open episodes are kept
suppressed_alerts 180 same as events (by timestamp)
alert_suppression_rules - never pruned
alert_notes, alert_ack_events, alert_deliveries - removed with their alert (orphans swept)
alert_delivery_cursors - never pruned

The day values are the code defaults; the shipped deployment/config/hpintel.env.example sets all HPINTEL_RETENTION_*_DAYS to 36500 (keep everything, ADR 0010).

Raw Cowrie files are pruned by cowrie-retention.timer: rotated JSON logs 30 days, TTY recordings 180 days, captured downloads 365 days.
