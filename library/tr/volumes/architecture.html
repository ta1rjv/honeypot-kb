Components #

Component Location Responsibility
Cowrie /home/cowrie on the VM; config in deployment/cowrie/ Medium-interaction SSH honeypot. Emulates a Linux server; never executes attacker commands. Writes JSON events, TTY recordings and captured files.
Collector backend/hpintel/collector.py Tails cowrie.json with a persisted offset (inode + byte offset in collector_state), handles rotation (also during downtime), truncation, partial lines. Database outages never advance the offset; deterministic bad lines go to dead_letters.
Normalizer backend/hpintel/normalize.py Maps Cowrie event ids to a stable event taxonomy (connection.inbound, auth.failure, command.input, payload.upload, ...), validates fields, converts timestamps to UTC, assigns deterministic event ids (UUIDv5 of the raw line) for idempotent re-ingest.
Store backend/hpintel/store.py One transaction per event. Raw event row first; primary rows (session, auth attempt, command) and derived rows (emulated processes, file operations, network activity, payload analysis, detection) in separate savepoints so analysis failures never lose raw telemetry.
Command parser backend/hpintel/cmdparse.py Splits shell lines (quotes, pipes, separators, redirections, wrappers like sudo/nohup/busybox; leading flow words such as then/do/if/! are dropped from a stage) into emulated processes, file operations and network intents. Results are labelled evidence="derived".
Detection backend/hpintel/detection.py Bounded regex rules plus contextual checks (download -> chmod -> execute chain, captured payload executed, brute force, scanners). Produces categories with confidence (Suspected < Likely < Observed < Confirmed), MITRE ATT&CK techniques with evidence strings and event ids, and a risk score. Incremental per-session state. File-name techniques (T1070.004 removal of a fetched, chmod +x or executed file, T1564.001 hidden path, T1036.005 daemon-named dropped file outside system dirs, T1571 for downloader URLs whose explicit port differs from the scheme default) are derived in CommandState; per-source-IP credential techniques (T1110.001, T1110.003) come from analytics_jobs.aggregate_credential_techniques because bots use one attempt per connection. Thresholds are assumptions, see docs/ASSUMPTIONS.md.
Payload analysis backend/hpintel/payloads.py sha256, size, magic-byte type, ELF header metadata, bounded printable strings. Files are only read, never executed or served.
TTY backend/hpintel/ttylog.py, collector.TtyFollower Parses Cowrie ttylog records for replay and streams live output frames of active sessions over the bus.
Intel backend/hpintel/intel.py Asynchronous enrichment of source IPs: Team Cymru IP-to-ASN DNS, reverse DNS (switchable), optional local MaxMind-format database. Results are cached and labelled "external intelligence".
API backend/hpintel/api.py, main.py FastAPI app: JWT-authenticated REST API, first-message-authenticated WebSocket, public minimal health, Prometheus metrics, static dashboard with SPA fallback, security headers.
Housekeeping backend/hpintel/housekeeping.py Every 10 minutes: closes stale sessions (2 h without events), applies retention, raises disk usage alerts, re-analyses payloads that were unreadable at ingest (bounded batch, retry backoff); a rescan only fills in payload metadata and does not re-run detection or raise alerts. Then the analytics jobs of backend/hpintel/analytics_jobs.py, each bounded per run and never raising: command-sequence hashes of closed sessions (campaigns), payload enrichment (entropy, heuristic IoCs, 64 KiB head hash), byte-by-byte prefix verification of payloads that share a head hash, per-source-IP credential techniques (T1110.001 guessing, T1110.003 spraying; techniques only, no alerts or classifications), and one system_samples row for the Health trend. python -m hpintel.cli backfill-analytics runs the hash and payload jobs until the backlog is empty; redetect-techniques inserts MITRE technique rows that new rules would have produced for stored sessions.
Analytics API backend/hpintel/api_stats.py, api_intel.py, api_alerts.py, api_system.py, api_payload_intel.py Read-only aggregates over a half-open UTC time window (timewindow.py: minute/hour/day buckets, at most 366 days): KPIs, heatmap, funnel, top lists, credentials, time patterns, geo, MITRE matrix, campaigns (including heuristic script clusters), SSH fingerprints, new-in-window values (TTL single-flight cache), IP profile, payload families, IoC export (optionally with heuristic indicators); plus alert search, bulk acknowledge and notes, the system trend, the systemd unit state (fixed systemctl show argv, one-minute cache), host status, containment trend and notification state. Routers are included by main.py.
Roles backend/hpintel/auth.py, api.py (require_user, require_admin) Two roles (0.4.0): admin and the optional read-only viewer. The token carries a role claim that is re-checked against the configured accounts on every request; write routes depend on require_admin (403 for the viewer).
Weekly report backend/hpintel/reports.py, api_reports.py Builds the weekly report from the same internal query functions as the analytics endpoints (no HTTP self-calls); deterministic, escaped Markdown rendering; per-period cache.
Notifier backend/hpintel/notify.py Optional (HPINTEL_WEBHOOK_URL). Background loop every 30 s: posts new alerts at or above the minimum severity to one HTTP(S) receiver (HMAC-signed when a secret is set), deduplicated through alert_deliveries, bounded by a persisted per-channel high-water mark (alert_delivery_cursors). ADR 0011.
Dashboard dashboard/ React 19 + TypeScript + Vite single-page app, served by the backend. Every route view is loaded lazily (React.lazy, failed chunk loads retried through the error boundary); filter and time-range state is kept in the URL (Copy link button); sticky table headers inside bounded scroll boxes. Views: Suppression (rules and the suppressed alerts log), Overview, Live Attacks, Live Terminal, Sessions (+detail, compare), IP Intelligence, Campaigns, New in range, Credentials, SSH fingerprints, Payloads, IoC Export, Processes, Files, Network, Attack Analysis, ATT&CK Matrix, Alerts, Timeline, Time patterns, Weekly report, Replay, Search, Health. Write controls (acknowledge, notes) are hidden for the viewer role.

Data flow of one command #

  1. Attacker types wget hxxp://x/b.sh; chmod +x b.sh; ./b.sh in the emulated shell.
  2. Cowrie writes cowrie.command.input to cowrie.json and output bytes to the session's ttylog. The download itself never succeeds: Cowrie refuses non-global addresses on its own (text log only, no JSON event; observed in the attack simulation), and any real connection attempt by uid cowrie is dropped by nftables. Shell redirections into files (e.g. echo ... >> ~/.ssh/authorized_keys) are logged by Cowrie as cowrie.session.file_download with the written content.
  3. The TTY follower publishes the output frames to /ws subscribers (Live Terminal).
  4. The collector reads the line, the normalizer produces command.input, the store inserts events + commands, derives processes wget, chmod, ./b.sh, a file operation, a network intent (attempted), and runs detection: downloader (Likely), malware_deployment (Likely, chain), techniques T1105, T1222.002, T1059.004.
  5. Severe categories at confidence >= Likely raise a deduplicated alert (per session; a malware_deployment finding without a captured payload transfer and without a download -> execute chain, e.g. a chmod +x capability probe, raises a medium alert deduplicated per source IP and UTC day); event, session and alert messages are published to /ws. Every alert (detection, new_payload, disk usage) passes through store._alert, where the suppression rules of backend/hpintel/suppression.py (ADR 0013) can demote it (created at a lower severity, original kept) or suppress it (one suppressed_alerts row instead of an alert, nothing published or notified); rules are cached for 30 s, and a housekeeping pass demotes recent alerts once their session command hash exists. Events, sessions and classifications are never touched and alerts are never deleted.

Key decisions #

See docs/decisions/ for the full records. Summary:

  • Containment by uid: the cowrie uid has no network egress at all (including loopback), at the cost of attacker downloads failing; payloads are still captured via SCP/SFTP uploads.
  • SQLite (WAL) with a portable SQLAlchemy Core schema and a versioned migration runner, so PostgreSQL can be adopted later.
  • Webhook alert notifications are opt-in, limited to one IPv4 address and port for uid hpintel, signed and never sent for the backlog; SMTP is deferred (ADR 0011).
