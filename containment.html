Containment

Principle: realism never overrides containment. A compromised or abused honeypot must not scan, attack, relay or send spam to third parties, and must not reach the management plane. Sources: the threat model and the project's penetration test (not published).

Controls

Control What it does Reference
Default-deny egress The nftables output policy is drop; the forward policy is drop; ip_forward is 0. ADR 0003
Containment by user id Every new connection from the honeypot user is dropped, including loopback, before any accept rule. Attacker downloads therefore fail by design and are recorded as failed attempts and network intents. ADR 0003
No tunnels SSH forwarding is disabled in Cowrie; direct-tcpip channels are refused. Penetration test
Unprivileged services Cowrie holds only the capability to bind tcp/22; the backend holds no capability at all. systemd hardening is applied to every unit. ADR 0002
Narrow opt-in egress Alert channels and (planned) reputation lookups each need their own explicit rule for the backend user: one address and port, never the honeypot user. Without the keys the ruleset is byte-identical to the default. ADRs 0011, 0015, 0018
Availability watchdog A watchdog restarts the honeypot if it stops responding. VALIDATED
Management plane Management access is restricted; the dashboard listens on loopback only and is reached through an authenticated tunnel. Architecture

Availability

The same test found one availability problem of the honeypot itself; it is not a host compromise and not a containment break. Release 0.3.1 added an availability watchdog: a watchdog restarts the honeypot if it stops responding (VALIDATED on a disposable test VM, 2026-10-11).

Residual risks

A skilled attacker can detect that the host is an emulation (accepted risk of medium-interaction honeypots; see the threat model and Research). Reboot: a reboot of the production host was VALIDATED on 2026-10-10 (18:38 UTC) with release 0.2.x/0.3.0; a production reboot with release 0.3.1 and later is NOT RUN. Scenario-based reboots (reboot persistence after install and upgrade) were VALIDATED on disposable VMs. IPv6 behaviour is UNKNOWN (the host has no IPv6).
