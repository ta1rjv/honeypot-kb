Observed Campaigns

These groups come from the analyst triage reports of the first two weeks of production traffic (2026-10-08, 2026-10-10, 2026-10-11, 2026-10-15) and the attack pattern note. The evidence level of all triage data is MEASURED (read-only inspection of the live database). No captured file was executed; analysis of binaries is static and string-based. Source addresses are not repeated here; use the indicator tables.

Group B - Go SSH loader capability probe

A client announcing SSH-2.0-Go logs in as root with common passwords and runs one fixed sequence: set PATH, profile the system with uname, then write a tiny script that echoes a marker, make it executable, run it and delete it. It is a pre-flight check for a loader, not malware; the real second stage would only be fetched if the probe succeeds, and it never was. The command sequence is byte-identical across sessions (a single command hash).

  • Maps to reconnaissance and a download/execute pattern; MITRE T1082, T1222.002, T1059.004.
  • Seen from many addresses of a few hosting networks; by 2026-10-11 the probe hash appeared in 87 sessions from 11 addresses of one ASN between 2026-10-07 and 2026-10-11 (MEASURED).
  • Detection overfired: at severity high with per-session de-duplication this single probe generated about 90 % of the open alerts on 2026-10-10. The response was tuning (severity medium, de-duplication per address and day, 2026-10-10) and later a seed suppression rule that demotes the known probe to low (0.5.0).

Group C - SSH propagation worm, key and config drop

A SSH-2.0-Go client logged in with a default credential pair and staged two files: a permissive SSH client configuration (host-key checking off) and an SSH private key. This is the classic pattern of dota/outlaw-family SSH worms: the dropped key and configuration let a compromised host reach further targets non-interactively. MITRE T1105, T1098.004, T1021.004. The same source returned four more times (2026-10-08 to 2026-10-10) with the same one-line key drop. The honeypot's default-deny egress prevented any onward spread, which is the clearest real-world confirmation of the containment design. The key content is deliberately not reproduced.

Group D - SFTP upload named sshd (Go SSH worm with miner configuration)

Several sources in China, India and elsewhere brute-forced a login, uploaded a file named sshd over SFTP and often ran no command at all (one ran chmod +x and nohup, which only executed inside the emulation). Triage of 2026-10-10 and 2026-10-15 found:

  • All captured copies, across hashes, are byte prefixes of one binary; the different SHA256 values are an artifact of truncation (upload cap of 20 MiB, or the session dropping). The longest copy so far is about 30 MB.
  • ELF 64-bit x86-64, a Go program; string indicators include an attack queue of credentials, an SFTP library, a PAM library reference, system-information libraries, a mining configuration structure (algorithm, pool address, pool user and password, NiceHash flag), public-IP lookup services and a chat-service webhook for reporting. Assessment: a self-spreading SSH brute-force bot carrying a cryptominer configuration. Confidence MEDIUM (string-based, never executed); pool address and wallet were not found in the captured prefix; family name UNKNOWN (no hash lookup done).
  • MITRE T1105, persistence (T1543 candidate).
  • Two collection gaps were found and recorded: uploads were not marked as available by the collector, and the upload size limit truncates samples larger than 20 MiB.

Group E - kaz.sh download-and-run dropper

On 2026-10-13 around 11:27 UTC, one address in a Baltic-registered hosting ASN opened three sessions within ten seconds, each a root login with a different weak password (credential spraying), each sending a single command chain: uname -a, cat /etc/os-release, then a curl fetch of a script named kaz.sh from hxxp://74[.]113[.]234[.]62:5521/akzmahazcA/kaz.sh piped to bash, with wget and a kz.sh variant as fallback. The fetch was never made: the network intents are derived from the command text, there is no payload event and the honeypot egress counter did not change. The script content is therefore unknown, and no other source used this URL (MEASURED).

Understanding what such links deliver is the motivation for the proposed out-of-band retrieval design, ADR 0014, which is deferred and has no code (PROPOSED).

Simulated patterns

The platform also recognizes patterns reproduced in a lab with documentation addresses on 2026-10-07 (credential guessing, host reconnaissance, download-and-execute chains, cron and SSH-key persistence, trace removal, credential-file access, miners). Those are marked "Simulated", not observed, in the attack pattern catalogue.
